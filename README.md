# Облтех: перенос задач · версия 0.3.3

Расширение Chrome переносит задачи из общей Jira в Redmine или локальную Jira разработчиков. Использует ваш вход в этом же профиле браузера. Пароли не запрашиваются и не сохраняются. Исходная задача не изменяется.

## Что изменилось

- Добавлен фирменный сине-голубой значок «Облтех» в панель Chrome, список расширений и вкладку утилиты. Использован знак из официального SVG без надписи, чтобы он был различим в малом размере. Подготовлены PNG 16, 32, 48 и 128 px. После обновления закрепите расширение в панели Chrome через меню с пазлом и значок булавки.

- Кнопка **«Сбросить предыдущий перенос»** добавлена в компактное окно и полную форму. После ошибки она очищает незавершённое состояние, снимает блокировку предыдущей задачи и позволяет начать другую. Введённые ссылка, дата, имя, настройки и текущая прочитанная задача сохраняются.
- Сброс доступен только после остановки выполнявшейся операции. Работающий перенос нельзя отсоединить от его состояния: во время него кнопка недоступна. После сброса загрузка старого переноса автоматически не возобновляется.
- Созданные на сервере задачи, комментарии, загруженные файлы и история завершённых переносов не удаляются. Если номер созданной задачи известен, он сохраняется только как подсказка для последующего поиска, без состояния возобновления. Если ответ о создании был потерян, сброс не означает, что сервер ничего не создал — при необходимости проверьте список задач.

- Кнопка **«Перенести / обновить»** каждый раз заново читает исходную Jira и проверяет задачи выбранного проекта назначения. Проверяются открытые и закрытые задачи на всех страницах результатов. Совпадение определяется **только по последним пяти цифрам в конце заголовка**, например `[21783]`. Различие названий не мешает обновлению. Распознаются `Название [21783]`, `Название[21783]` и `Название 21783`.
- Найдена одна задача с номером — обновляются её название и данные. Ни одной — создаётся новая. Несколько задач с одним номером — утилита показывает ссылки и останавливается, даже если названия различаются. Ошибка поиска или явно другой первоисточник также останавливают перенос, без создания новой задачи. Уже существующие дубликаты автоматически не удаляются.
- При обновлении название и **всё описание** заменяются актуальной постановкой Jira, срок и постановщик — введёнными значениями. Статус, исполнитель, проект, трекер и приоритет существующей задачи сохраняются. Комментарии и прежние вложения сохраняются.
- Текущие изображения и MHTML добавляются с контрольной суммой в имени. Одинаковые версии файлов в существующей задаче повторно не загружаются; изменённая картинка, даже с тем же размером, получает новое имя. В описании используются актуальные версии. Архивы MHTML могут меняться при каждом захвате из-за содержимого страницы.
- После завершённого переноса кнопка остаётся доступной для актуализации. Локальная история используется как подсказка для поиска, а не как запрет обновления.

- Официальный логотип и палитра сайта `oblteh.ru` в компактном окне и полной форме. SVG включён в расширение и не загружается с сайта при использовании.
- Поле «Имя и фамилия постановщика» в основном окне и полной форме. Значение запоминается. Допускаются оба порядка имени и фамилии; отчество в учётной записи не мешает поиску. При совпадении нескольких пользователей нужен полный вариант имени или логин. Ошибка поиска останавливает перенос, другой пользователь молча не подставляется.

- Переключатель «Куда перенести»: **Redmine** или **Локальная Jira · KIS**.
- Локальная Jira: `http://jira.oblteh:8080`, проект **KIS**, тип **Доработка**.
- Вкладка утилиты **не открывается автоматически**. Перенос выполняется в невидимом документе расширения; окно можно закрывать и открывать для просмотра состояния.
- Кнопка **«Открыть вкладку ↗»** открывает полную форму и настройки по вашему желанию. Эту вкладку также можно закрыть, не останавливая работу.
- Вкладки самих сайтов используются для авторизации, сохранения MHTML и отправки данных. Открытый браузер и доступ к сети нужны до завершения переноса.
- При ошибке загрузки файлов в локальную Jira повторный запуск продолжает загрузку в уже созданную задачу.

## Установка и обновление

Chrome 116 или новее. Распакуйте архив в постоянную папку. В `chrome://extensions` включите режим разработчика и выберите «Загрузить распакованное расширение» — папку с `manifest.json`.

Если расширение уже установлено, **замените файлы в прежней папке**, обновите его через `chrome://extensions`. Не удаляйте расширение и не устанавливайте вторую копию: сохранится история и прогресс. Chrome может запросить разрешение на доступ к локальной Jira. Старые вкладки утилиты после обновления можно закрыть: при необходимости откройте новую форму кнопкой из окна расширения. Не обновляйте расширение посреди выполняющегося переноса.

Перед первым переносом локальной Jira нажмите «Прочитать задачу» заново: старое сохранённое описание предыдущих версий не содержит вариант Wiki для локальной Jira.

## Использование

1. В этом же профиле браузера войдите в общую Jira и систему назначения.
2. Нажмите значок расширения. Введите ссылку общей Jira, дату, имя и фамилию постановщика и выберите систему назначения.
3. Нажмите «Прочитать задачу». Проверьте название и список страниц для MHTML. Исходная задача сохраняется всегда; ссылки внутри связанных страниц дальше не обходятся.
4. Нажмите «Перенести / обновить». Утилита заново прочитает постановку и найдёт задачу по конечному номеру в выбранном проекте. Если найдена одна — обновит её вместе с названием; иначе при отсутствии номера создаст новую. Предоставьте доступ к выбранным дополнительным сайтам по запросу Chrome. Если после перечитывания появились ссылки на новые сайты, проверьте список и нажмите кнопку ещё раз для выдачи доступа.
5. Откройте результат и проверьте описание, изображения и срок. Закрытие всплывающего окна или полной формы не останавливает перенос.

Файлы также сохраняются в `Загрузки/Jira-Redmine/КЛЮЧ-ЗАДАЧИ/`. До подтверждения скачивания создание задачи не начинается. В настройках Chrome желательно отключить запрос места сохранения каждого файла.

## Общие правила

- Название исходной задачи и последние пять цифр её ключа: `Название [21890]`.
- Ссылка на первоисточник в конце описания.
- Изображения из описания прикладываются отдельными файлами и отображаются в соответствующих местах текста с шириной 800 px и сохранением пропорций.
- По возможности скачивается оригинальное изображение из вложений Jira, а не миниатюра. Значки ZIP/PDF, аватары и логотипы интерфейса не копируются как изображения задачи. Если изображений в описании нет, отдельные файлы изображений не создаются.
- Архивы исходной задачи, связанных задач и выбранных страниц документации прикладываются файлами, без отдельного комментария.
- История завершённых переносов различает Redmine и локальную Jira: одну исходную задачу можно перенести в обе системы.

## Redmine

Адрес: `https://rm.oblteh.ru/redmine`. Проект «КИС ЕМИАС», трекер «Доработка», статус «Новая», приоритет «Высокий». Постановщик выбирается по введённому имени и фамилии из списка поля «Постановщик задачи». Фактические названия проектов на вашем сервере можно загрузить в полной форме.

Дата ставится в дополнительное поле **«Выполнить до»**, а не в стандартный срок завершения. Описание преобразуется в Textile. Изображения вставляются через `!{width:800px}image-1.png!`. Вложения передаются через файловые поля формы создания. Проверяются ссылки на вложения и отображение изображений после создания.

## Локальная Jira

Адрес: `http://jira.oblteh:8080`, проект **KIS**, тип **Доработка**. Задача из присланной ссылки `KIS-1373` не изменяется и не служит шаблоном: из ссылки взяты адрес и проект.

Описание использует исходную Wiki-разметку Jira, а не Textile. Ссылки на изображения заменяются именами новых вложений: `!image-1.png|width=800!`. Ссылки на исходные задачи и исходные файлы сохраняются с адресом общей Jira. Постановщик (reporter) определяется по введённому имени и фамилии. Если имя соответствует текущему пользователю, используется его учётная запись; иначе выполняется поиск пользователей локальной Jira. Возможность выбора другого reporter зависит от прав вашей учётной записи и доступности поля в проекте. Исполнитель не назначается утилитой; используется поведение проекта.

**Дата по умолчанию — стандартное поле срока Jira `duedate`.** При необходимости в полной форме укажите другое поле даты по названию или ID. Кнопка «Загрузить типы и поля из локальной Jira» выводит доступные варианты. Приоритет по умолчанию определяется проектом; при необходимости задайте его точное название в настройках.

Перед созданием проверяются тип задачи, поле срока, обязательные поля и доступность вложений. Если проект требует дополнительных полей без значений по умолчанию, утилита остановится и перечислит их: потребуется адаптация заполнения этих полей. Создание не продолжается с пустыми обязательными значениями.

После создания файлы загружаются через Jira REST API, затем сверяются имена, размеры вложений и сохранённый срок. При повторе уже загруженные файлы с тем же именем и размером не отправляются заново.

## Ошибки и повторный запуск

Если видите «Сначала завершите предыдущий перенос в выбранной ранее системе», нажмите **«Сбросить предыдущий перенос»**. Дождитесь сообщения о сбросе и продолжайте работу с новой задачей. Сброс не требует входа в Jira/Redmine и не требует заполнять срок или постановщика. После перезапуска браузера сброшенное состояние не восстанавливается.

Если нужен вход — авторизуйтесь во вкладке соответствующей системы и повторите запуск. Сохранённые MHTML и изображения переиспользуются при неизменных параметрах.

Если создание уже началось, но ответ потерян, повторная отправка блокируется. Откройте полную форму, проверьте задачи в системе назначения, включая закрытые. Если задача создана, укажите её ссылку. Для локальной Jira утилита проверит первоисточник в описании и позволит продолжить загрузку файлов в найденную задачу. Если задачи точно нет, подтвердите это отметкой и разрешите повторную отправку.

Если локальная задача создана, но загрузка вложений не закончилась, повторяйте перенос с **той же исходной задачей, системой, датой и списком страниц**. Сначала завершите этот перенос, затем начинайте другой. При остановке браузера состояние задачи и файлы сохраняются локально; после запуска браузера повторите перенос вручную.

Задачи с совпадающим конечным номером ищутся на сервере, включая переименованные, созданные вручную и после очистки локальной истории. Поиск выполняется ещё раз после сохранения архивов, прежде чем создать новую задачу. Одновременные создания с разных компьютеров не являются единой серверной транзакцией: полностью исключить гонку без поддержки сервера невозможно. Незавершённая отправка с неизвестным результатом по-прежнему требует проверки, а обновление уже известного номера можно безопасно повторить без создания новой задачи.

## Проверки и ограничения

Проверены локальные сценарии: форматирование ссылок и изображений, выбор проекта Redmine, отсутствие автоматического открытия вкладки, единственный невидимый рабочий процесс, маршрутизация сообщений, разделение истории по системам, подготовка полей KIS, дозагрузка после потери ответа и блокировка неопределённого создания.

**Создание и обновление на ваших серверах в версии 0.3.2 не проверены.** Адрес `jira.oblteh` доступен в вашей сети. Возможно уточнение настроек вашей версии Jira/Redmine. Первый запуск выполняйте на согласованной тестовой задаче. Поддерживается Jira Server/Data Center с REST API v2 и Wiki-описанием; формат Atlassian Document Format (ADF) не поддерживается. Для обновления Redmine используются форма редактирования, токен и версия записи; REST API Redmine включать не требуется. Для локальной Jira используются поиск, editmeta и PUT существующей задачи.

Точное совпадение произвольных стилей, макросов, объединённых ячеек и интерактивных компонентов не гарантируется. MHTML — снимок открытой страницы, а не серверная резервная копия. Скрытые блоки и интерактивные компоненты проверяйте вручную. Изображения в CSS, фоновые картинки и отдельные не-графические вложения автоматически не копируются. Лимит Redmine взят из записи — 50 МБ; в локальной Jira читается серверный лимит.

Пароли и cookies не считываются: запросы выполняются во вкладках сайтов с существующей авторизацией. Описания, ссылки, история и файлы хранятся локально в расширении; скачанные файлы остаются в загрузках. Никакие сторонние сервисы не используются. Доступ выдаётся только сайтам, выбранным для переноса.

## Исходный код

- `popup.*` — компактное окно.
- `index.html`, `full.js` — полная форма, открываемая по кнопке.
- `engine.html`, `app.js` — невидимый процесс переноса.
- `updates.js` — поиск существующих задач, перечитывание исходника и обновление.
- `background.js`, `rpc.js` — обмен с Chrome API; offscreen-документ обращается к ним через сообщения.
- `injected.js` — фиксированные функции для выполнения во вкладках сайтов, без динамического выполнения строк кода.
- `core.js` — общие правила и подготовка полей.
- `tests/` — локальные проверки. `tools/build-engine.cjs` обновляет невидимую HTML-форму после изменения полной формы.

Сборка для установки не требуется. После правок обновите расширение в Chrome. Для изменения `index.html` дополнительно выполните `node tools/build-engine.cjs`.

Проверки: `node tests/core.test.cjs`, `node tests/retry.test.cjs`, `node tests/popup.test.cjs`, `node tests/local-jira.test.cjs`, `node tests/updates.test.cjs`, `node tests/reset.test.cjs`. Синтаксис: `node --check app.js` и аналогично для остальных JS-файлов. Проверены сопоставление по номеру, несколько совпадений, свежая постановка вместо локальной истории, появление задачи во время захвата архивов, сохранение статуса и исполнителя, обновление Jira без POST создания, повтор после потери ответа и замена одинаковых по размеру изображений. Для сброса проверены снятие блокировки, сохранение новых входных данных, запрет сброса активной операции, сохранение ссылки на созданную задачу, отсутствие блокировки новой задачи и ошибка записи состояния.

Документация: [Jira REST API](https://docs.atlassian.com/software/jira/docs/api/REST/8.20.10/), [создание Jira issue](https://developer.atlassian.com/server/jira/platform/jira-rest-api-example-create-issue-7897248/), [Chrome offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen), [Chrome MHTML](https://developer.chrome.com/docs/extensions/reference/api/pageCapture), [Textile Redmine](https://www.redmine.org/projects/redmine/wiki/RedmineTextFormattingTextile).
